# Lesson NN — 標題

## 目標

說明本課新增的observable capability。

## 核心觀念

解釋推理這項改動所需的最少觀念。

## 問題情境

具體展示本課開始前存在的failure、ambiguity或operational need。

## 改動前

描述或畫出改動前相關architecture。

## 改動後

描述或畫出本課導入的architecture delta。

## 先自己試試看

在揭露walkthrough前，提供一個範圍明確的design或coding prompt。

## 實作導覽

解釋重要code、SQL、configuration與transaction boundaries。使用file links，
不要把大量source code複製進lesson。

## 為什麼選這個設計

記錄alternatives、trade-offs，以及什麼條件會讓另一種選擇更合理。

## 如何測試

```bash
# 可以直接執行的commands
```

## 預期證據

列出相關API output、database state、logs、metrics或screenshots。不能只寫
「應該可以運作」。

## 故障實驗

說明如何安全地製造failure、事前要預測什麼、應觀察什麼，以及如何恢復系統。

## 理解題

1. 提出一個必須推理本課內容才能回答的問題。
2. 詢問移除某項關鍵機制後會出現什麼failure。
3. 要求學習者解釋一項trade-off或alternative。
